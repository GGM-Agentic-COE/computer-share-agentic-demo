Component Legend

Every visual pattern used above, and the token it maps to.

Status pill Text-labeled, not color-only (WCAG). status-incomplete / status-review / status-validated / status-submitted map to the four real FilingStatus values.
Primary button --brand-primary (#93186c), pill radius (100px) — matches the real site's .login-button and toggle-button radius pattern.
Card / panel radius 24px for cards, 20px for panels/overlays — the dominant radii found in the source CSS frequency analysis.
Icons Inline SVG only (bell, warning triangle) — no emoji anywhere in this document or the product UI, per EA11.
Typography Manrope throughout — the single face found across the entire source site.
Annotation box Documents a real behavior or a known gap directly on the wireframe — not decorative, encodes traceability back to user-flows.md.
Source screens: ui/src/pages/ExecutiveHome.tsx, ComplianceDashboard.tsx, FilingReview.tsx, ui/src/components/NotificationBell.tsx. Design tokens: docs/design/computershare-design-system.md. Flow detail: docs/sdlc/phase-4-design/user-flows.md. The Interactive Prototype above runs on fake local data via vanilla JS, entirely client-side — it never calls the real API. The per-epic reference cards below it are static, hand-built HTML/CSS annotated with feature/story IDs; layouts mirror the real app but nothing in them is wired up.
